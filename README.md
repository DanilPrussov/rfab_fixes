# RFAB: отдельные исправления

Рабочее место для исправлений Skyrim RFAB, которые можно передать авторам сборки.
Одна проблема — один каталог в `fixes/` и отдельный устанавливаемый мод MO2.
Разработка ведётся на macOS; компиляция DLL не входит в задачи проекта.
Локальный Git-репозиторий инициализирован; удалённый репозиторий пока не подключён.

```text
mod_fix/
├── AGENTS.md              # правила для работающих здесь агентов
├── BACKLOG.md             # ещё не начатые задачи
├── docs/
│   ├── WORKFLOW.md        # от воспроизведения до включения в RFAB
│   └── ENVIRONMENT.md     # расположение сборки и границы проверки на Mac
├── fixes/
│   └── 0001-short-name/   # появится при создании первой задачи
│       ├── README.md     # проблема, причина, базовые версии, решение
│       ├── TESTING.md    # сценарии и фактические результаты проверок
│       ├── UPSTREAM.md   # инструкция для авторов RFAB
│       ├── payload/      # содержимое Skyrim Data, без самой папки Data
│       ├── src/          # при необходимости: исходники и преобразования
│       └── evidence/     # небольшие доказательства, diff, хеши
├── templates/fix/        # заготовка нового фикса
├── tools/fix.py          # создание, проверка структуры и ZIP
├── tests/                # проверки инструментов проекта
├── dist/                 # локальные установочные архивы, вне Git
└── scratch/              # временные копии и большие материалы, вне Git
```

Каталоги `dist/` и `scratch/` создаются по необходимости. Пример `0001-short-name`
не является уже выполненным исправлением.

## Начать задачу

Из корня проекта, Python 3.10+ без сторонних библиотек:

```sh
python3 tools/fix.py new 0001-short-name
python3 tools/fix.py check 0001-short-name
python3 tools/fix.py package 0001-short-name
```

После `new` заполняем описание и кладём только изменённые игровые файлы в
`payload/`. Например, `payload/SKSE/Plugins/Example.ini`. Пустой фикс проверку
не проходит. ZIP содержит только файлы из `payload/`, с путями от корня `Data`.
Описание и инструкцию из `UPSTREAM.md` передаём авторам отдельно.

`check` проверяет структуру пакета; синтаксис конфигов и поведение Skyrim нужно
проверять отдельно. `package` также не означает, что фикс прошёл игровую проверку.
Выпущенный ZIP не перезаписывается: предыдущий архив сохраняем вне `dist/` или
удаляем осознанно перед следующей упаковкой; его SHA-256 записываем в `TESTING.md`.

## Как будем работать

1. Получаем баг, шаги воспроизведения и ожидаемый результат.
2. Находим причину и фактически используемый файл с учётом профиля и конфликтов.
3. Делаем минимальное исправление и проверяем его доступными на Mac средствами.
4. Собираем отдельный мод для проверки на Windows в MO2/Skyrim.
5. Фиксируем результат, готовим инструкцию интеграции и передаём авторам RFAB.
6. После включения записываем версию сборки, в которой исправление принято.

Подробности — в [процессе разработки](docs/WORKFLOW.md).
Первые удобные задачи: ошибки в текстовых переводах, INI/JSON/TOML,
конфигах MCM и существующих правилах плагинов.

Дальше стоит добавлять автоматизацию под реальные повторяющиеся задачи:
проверки конкретных форматов и снимки затрагиваемых файлов. Общий мегапатч,
копия всей сборки и отдельный фреймворк для каждого фикса пока не нужны.
