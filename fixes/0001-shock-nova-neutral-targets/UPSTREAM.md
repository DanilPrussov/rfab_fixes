# Передача 0001-shock-nova-neutral-targets авторам RFAB

## Состояние

Кандидат `ready-for-test`, подготовлен 2026-10-20; игровой проверки нет.
Установка на Windows — по [INSTALL.md](INSTALL.md).

## Причина и предлагаемая правка

Комплект из «Критического разряда» и «Высвобожденного электричества»
выбирает враждебную цель в `RFAB_Spell_ElectricVortex`, но конечный
`RFAB_Spell_FingerOfTheMountain` наносит урон по площади без фильтра
нейтральных получателей. Наблюдение согласуется с описанным попаданием
по оркам при атаке великана; штраф и репутация не воспроизведены локально.

В кандидате через Mutagen 0.54.4 добавлено Target Condition
`IsHostileToActor(PlayerRef [00000014]) == 1`, Run On Subject,
на MGEF `1124AF`
`WB_D100_FingersOfTheMountainNew_Effect_LightningStrike` в `RFAB.esp`.
Local ID дан без load-order-префикса. Сначала проверить Referenced By:
локально MGEF используется только тремя ступенями конечного SPEL `1124B1`.
Если на актуальной базе есть другие потребители, выделить отдельный MGEF
и перенаправить только три EFID указанного SPEL.

Урон, Area, длительность, перки, Hostile и остальные флаги сохранены.
PEX не менялся. Игровых DLL нет. Сборка .NET-инструмента нужна только
для воспроизведения ESP; пользователю для установки она не нужна.
Успех зависит от A/B-проверки побочных событий.

## База, файлы и зависимости

- База: локальный `mods/RFAB/RFAB.esp`, версия RFAB неизвестна.
- SHA-256: `a5b03f58aeefeb806f7c4e44981d4f3ba0bc125419d488d3fcc7a896768d3401`.
- Остальные исследованные файлы/хеши:
  [source-manifest.json](evidence/source-manifest.json).
- Payload: `RFAB-ShockNova-NeutralTargets.esp`, 799 байт, один override MGEF.
- Прямые мастера: `Skyrim.esm`, `RFAB.esp`. Обычный ESP, HEDR 1.7,
  formVersion 44, без новых записей и ESL-флага.
- SHA-256 ESP: `640c860aca45858c89946ecc34a92a178022428f8d3e060ced1edc4a68d94994`.
- Патч должен загружаться после RFAB и выигрывать изменяемую запись.
  Приоритет файлов MO2 отдельно важен при одинаковых именах файлов;
  новый ESP не требует замены файла `RFAB.esp`.
- Потребуются штатные зависимости RFAB; новые runtime/SKSE-зависимости
  для кандидата не предполагаются.

## Интеграция после успешного теста

1. Сверить текущую базу и цепочку записей с материалами исследования.
2. Перенести только условие в исходный RFAB.esp через xEdit/CK,
   сохранив изменения авторов в остальных полях.
3. Повторить контрольные сценарии из [TESTING.md](TESTING.md).
4. Проверить, что отдельный тестовый патч больше не перекрывает обновлённую базу.

Сейчас других фиксов в проекте нет. Любой будущий override `1124AF`
необходимо объединять на уровне записи; один порядок загрузки
не сохраняет автоматически правки обоих патчей.

Условия распространения ресурсов RFAB не установлены. Для внешней передачи
предпочесть этот минимальный рецепт и результаты тестов; полную RFAB.esp,
чужие PSC/PEX и DLL не включать.
